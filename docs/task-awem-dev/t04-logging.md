## 功能点

### F1 · 执行器日志收割管道（LogSink）

- **开发状态**：🟠 已完成
- **检查状态**：✅ 通过（2026-10-25 自检）
- **开发描述**：提供 `LogSink` 抽象：每执行器一个 `<name>.log` 写入器（`data/logs/executors/`），实现 `io.Writer`（stdout/stderr 汇入同一文件，T05 挂接）；写入线程安全（多 goroutine 并发写不交错撕裂）；对外暴露打开/关闭（执行器删除 --purge 时关文件）。行缓冲策略（及时落盘供 tail，又不逐字节 flush 拖性能）自定并记录。
- **验收要点**：
  - 并发写单测（多 goroutine 各写 N 行，结果行数完整、无撕裂行）；
  - Close 后再写返回错误不 panic；
  - 文件出现在 §5.1 约定路径。

### F2 · 按大小滚动

- **开发状态**：🟠 已完成
- **检查状态**：✅ 通过（2026-10-25 自检）
- **开发描述**：单文件达到 `max_size_mb`（默认 50）滚动：`<name>.log` → `<name>.log.1`（旧链依次后移，保留个数与保留策略联动）或时间戳后缀方案——**选一种记录到变更记录**；滚动瞬间写入不丢、不阻塞收割（换文件对 Writer 透明）；滚动可配上下限保护。
- **验收要点**：
  - 单测：写超过阈值 → 产生滚动文件、新文件从空继续；
  - 滚动边界无丢行（总行数守恒断言）。

### F3 · 保留策略清理

- **开发状态**：⬜ 未开始
- **检查状态**：⬜ 未检查
- **开发描述**：按 `retention_days`（默认 7）清理过期滚动文件；触发时机：daemon 启动时 + 周期（如每日，间隔自定记录）；清理动作写一条事件（F4）。空间兜底：可选"总占用超限告警事件"（不自动删，避免误删）。
- **验收要点**：
  - 单测：构造新旧文件 → 只删过期；mtime 用注入时钟控制；
  - 清理产生事件记录。

### F4 · 管理事件日志（events.log）

- **开发状态**：⬜ 未开始
- **检查状态**：⬜ 未检查
- **开发描述**：`data/logs/events.log` 记录管理事件：启停/崩溃/自动重启/配置加载（成功与失败）/配置变更/服务安装/日志清理等。格式选型（建议 JSONL：时间、类型、执行器（可空）、详情；理由记录）；提供类型化写入 API（`logs.Event(EventStart, name, detail)`）供全项目调用；同样受滚动/保留管理（事件日志体量小，可与执行器日志共用参数或单独放宽，取简单方案并记录）。
- **验收要点**：
  - 单测：写事件 → 读回 JSONL 解析成功，字段齐；
  - 事件类型枚举覆盖 §11 列举的场景（常量定义）。

### F5 · --debug 透传支持

- **开发状态**：⬜ 未开始
- **检查状态**：⬜ 未检查
- **开发描述**：执行器配置中的 debug 开关（来自 T03 解析的 `--debug`）在日志层可查询（供 T05 spawn 时附加参数）；`awem add` 时的提示文案数据（上游文档警告：debug 的 rotated 诊断日志长跑占磁盘，默认关）放到事件/文档层提示。本功能点主要是把开关贯通到日志与事件（记录"某执行器以 debug 启动"事件）。
- **验收要点**：
  - 单测：debug=true 的执行器启动事件含 debug 标记；
  - 默认 false 时无额外行为。

### F6 · tail 与跟随读取接口

- **开发状态**：⬜ 未开始
- **检查状态**：⬜ 未检查
- **开发描述**：提供读取接口（供 CLI `awem log -f` 与 Web WS 共用）：`Tail(name, lines)` 返回尾部 N 行；`Follow(name)` 流式推送新行（channel/回调），**滚动切换后自动跟随新文件**；历史分页读取（详情页向上翻页用，按行偏移或分页策略自定记录）。文件不存在返回明确"无日志"信号（CLI 显示、Web 空状态）。
- **验收要点**：
  - 单测：写 K 行 → Tail(N<K) 返回最后 N 行；
  - 持续写入 + 中途滚动 → Follow 订阅者无漏行；
  - 文件不存在不报错、返回空态。
