# awem 开发任务规范（所有子任务必守）

- **适用范围**：`docs/task-awem-dev/` 下全部子任务（T01–T11）。执行任何一个子任务前必须通读本文；每个子任务文档内的"规范速查"只是摘要，**不豁免本文其余条款**。
- **上位文档**：本规范服从 [AGENTS.md](../../AGENTS.md) 与 [design.md](../design/design.md)；冲突时以上位文档为准。

---

## 1. 文档优先原则（最高优先级）

1. **唯一设计基准是 `docs/design/design.md`**（v1 定稿，16 条核心决策 + D1–D10）。实现与设计冲突时：**停下 → 先改设计文档 → 征得用户同意 → 再改代码**。不许"先写代码以后再补文档"。
2. Web UI 的视觉与交互以 [ui-guidelines.md](../design/ui-guidelines.md) 为准：**新增状态语义、新组件、新设计令牌，先更新规范再写代码**；组件只引用 `--awem-*` 变量，不写死色值。
3. 设计文档未定的实现细节（如 TOML/CLI 框架选型、状态枚举命名），由执行者自行决定，但**必须记入所在子任务文档的"变更记录"**，写清"选了什么、为什么"。
4. 发现任务文档本身与设计文档矛盾时：按设计文档执行，并在子任务文档"变更记录"里登记矛盾点，等用户确认后修文档。

## 2. 红线（不可越界，见 design.md §2）

- ❌ 不做任务派发（dispatch 是平台调度器的事）。
- ❌ 不做多机聚合面板（看全局去平台"执行器"页）。
- ❌ 不做平台**写**操作：v1 对平台只读，MCP 通道仅允许 `list_projects` / `list_executors` / `get_executor_launch_config` 三个只读工具（白名单在代码层强制）。
- ❌ v1 不做内置 MCP server（v1.5 再加）；launchConfig 回写留 v2。
- ❌ 本地 API 只绑 `127.0.0.1`，不提供多用户/远程访问。

## 3. 工程约定（design.md §16）

- Go 单 module（module 名 `awem`），二进制名 `awem`；目录：`cmd/awem/`、`internal/`（config / supervisor / platform / api / logs 等）、`web/`（React SPA，构建产物 `go:embed` 进二进制）。
- 注释与文档中文，标识符英文。
- 测试：单测覆盖命令解析 / import / 守护状态机 / 配置校验；冒烟测试用**假长驻子进程**（启停 / 崩溃拉起 / 日志收割），不依赖真实平台与 npx。
- 每个 Go 包新增代码须 `go build ./...`、`go vet ./...`、`go test ./...` 三绿后才算功能点完成。

## 4. CLI 约定（design.md §8）

- 全局 flag：`--json`（稳定 schema，字段增改须向后兼容）、`--yes`（跳过确认）。
- 幂等：重复 add 同名 → "已存在"退出码 4，不覆盖；start 已运行 → no-op 成功。
- 退出码固定：`0` 成功 / `2` 用法错误 / `3` 未找到 / `4` 已存在 / `5` daemon 未运行（且无法自动拉起）/ `1` 其他。
- 破坏性操作（remove、stop 全部）必须显式确认。

## 5. 安全约定（design.md §10）

- API 仅绑 `127.0.0.1`；`data/api-token` 首次生成用 `crypto/rand`，权限 0600（Windows 设 ACL 仅当前用户）。
- token、MCP 令牌、执行器 token 明文落盘仅限 `config.toml` 与 `data/api-token`（0600）；不加密（keychain 留 v2）。
- API 校验 token 头 + Host/Origin 防 CSRF。
- 日志与 `--json` 输出里不主动回显完整敏感令牌（展示用掩码；Web 表单敏感字段默认掩码 + 眼睛切换）。

## 6. 状态机与状态字典（全目录统一）

**子任务状态 / 功能点开发状态**（5 态）：

| 状态 | 标记 | 含义 |
|---|---|---|
| 未开始 | ⬜ | 尚未动工 |
| 进行中 | 🔄 | 正在开发（子任务级：至少一个功能点动工） |
| 已暂停 | ⏸️ | 中途停下，**必须在"变更记录"写原因与恢复条件** |
| 已完成 | 🟠 | 代码写完 + 单测/自测通过，但未经过检查环节 |
| 已检查 | ✅ | 检查环节逐功能点对照验收要点通过 |

**功能点检查状态**（3 态）：⬜ 未检查 / ✅ 通过 / ❌ 不通过（打回）。

**流转规则**：

- 未开始 → 进行中 → 已完成 → 已检查，单向推进；进行中 ⇄ 已暂停。
- 子任务状态由功能点状态推导并手工同步：全部功能点 🟠 → 子任务 🟠；全部功能点 ✅ → 子任务 ✅。
- 检查发现问题的功能点：开发状态打回 🔄、检查状态 ❌，修复后重新走"已完成 → 检查"。打回要留痕，不许删除历史记录。

## 7. 状态更新与记录规则

1. 状态落盘在两处：子任务文档（顶部状态行 + 各功能点）与 [index.md](index.md)（总览表），**每次改动两处必须同步**。
2. 每次状态变化在子任务文档"变更记录"和 index.md"更新记录"各加一行：`| 日期 | 动作 | 一句话说明 |`。
3. 开工即改状态（⬜→🔄），不许"干完再补"——中途断掉时状态必须能反映真实进度。
4. 功能点完成时同步更新 index.md 的"功能点进度"列（`已检查数/总数`）。

## 8. 检查环节规则

- "已完成"≠"已检查"。检查是独立环节（可由用户发起，或开发会话收尾时自查 + 用户复核）。
- 检查必须**逐功能点**进行：跑验收要点里写的验证手段（执行测试、跑命令、读代码对照设计），**不许凭印象打勾**。
- 检查通过：功能点"检查状态"→ ✅，并在"检查记录"表登记（日期 / 功能点 / 结果 / 备注）。
- 检查不通过：登记问题，功能点打回 🔄（子任务同步回 🔄），修复后重新检查。
- 子任务全部功能点 ✅ 后：子任务状态 → ✅，index.md 同步。

## 9. 暂停与恢复

- 暂停（⏸️）必须写明：暂停原因、已完成到哪、恢复前提。
- 恢复时先读子任务文档全文 + 变更记录 + 检查记录，再继续，不重做已完成功能点。
