# awem Web UI 设计规范

- **状态**：v1 初稿（2026-10-24），随 web/ 实施迭代。
- **定位**：[design.md](design.md) §9 定义页面结构与功能；本规范定义**视觉与交互**。两者冲突时以 design.md 为准，并按"先改文档、再改代码"的流程修订。
- **适用**：`web/` 下 React SPA（`go:embed` 内嵌，仅 127.0.0.1 本机访问）。

---

## 1. 设计原则

1. **信息密度优先**：这是运维工具，不是营销页。一屏看清全部执行器的双状态（本地进程 + 平台）。
2. **克制的色彩**：中性灰为底，唯一强调色；彩色只表达状态与可操作项，不做装饰。
3. **操作直达**：start/stop/restart 行内完成；破坏性操作（remove、stop 全部）必须显式确认。
4. **状态即事实**：本地状态与平台状态**并列展示、不合并**，视觉上能区分来源（design.md 决策 #9）。
5. **轻量快速**：SPA 体积小、首屏快；动画少而短，且尊重 `prefers-reduced-motion`。

## 2. 设计令牌（Design Tokens）

落地为 CSS 自定义属性，命名 `--awem-*`；`:root` 为浅色，`[data-theme="dark"]` 覆盖为深色。**组件只引用变量，不写死色值。**

### 2.1 中性色与强调色

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--awem-bg` | `#ffffff` | `#0f1113` | 页面背景 |
| `--awem-bg-subtle` | `#f6f7f9` | `#16191d` | 卡片/面板背景 |
| `--awem-bg-muted` | `#eef0f3` | `#1e2227` | hover、填充、表头 |
| `--awem-fg` | `#1a1d21` | `#e6e8eb` | 正文 |
| `--awem-fg-secondary` | `#5a6169` | `#9aa1a9` | 次要文字 |
| `--awem-fg-faint` | `#8b9199` | `#6b727a` | 占位/禁用 |
| `--awem-border` | `#e2e5e9` | `#2a2f36` | 边框、分隔线 |
| `--awem-accent` | `#2563eb` | `#3b82f6` | 主按钮、链接、焦点环 |
| `--awem-accent-hover` | `#1d4ed8` | `#60a5fa` | accent 悬停 |

### 2.2 状态色（语义固定，不得挪作装饰）

| 语义 | 令牌 | 浅色 | 深色 | 用在 |
|---|---|---|---|---|
| 成功 / ONLINE | `--awem-success` | `#16a34a` | `#22c55e` | 本地"运行中"、平台 ONLINE |
| 忙碌 / BUSY | `--awem-busy` | `#2563eb` | `#3b82f6` | 平台 BUSY（与 accent 同色系，靠文字区分） |
| 停止 / OFFLINE | `--awem-off` | `#8b9199` | `#6b727a` | 本地"已停止"、平台 OFFLINE |
| 警告 / 漂移 | `--awem-warn` | `#d97706` | `#f59e0b` | 配置漂移黄标、崩溃重连中 |
| 错误 / 危险 | `--awem-danger` | `#dc2626` | `#ef4444` | 失败状态、破坏性操作按钮 |

状态一律"**圆点（8px）+ 文字**"双编码，不只用颜色（可访问性）。

### 2.3 字体与排版

| 令牌 | 值 | 用途 |
|---|---|---|
| `--awem-font-sans` | `-apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif` | 全局 UI |
| `--awem-font-mono` | `ui-monospace, "SF Mono", "Cascadia Mono", "JetBrains Mono", Consolas, Menlo, monospace` | 启动命令、token、executor-id、日志 |

- 字号阶梯：**12**（辅助/徽标）· **13**（表格、日志）· **14**（正文/表单）· **16**（小节标题）· **20**（页面标题）。
- 行高：正文 1.5；等宽日志 1.45。
- 数字与 ID 用等宽；正文不混用等宽字体。

### 2.4 间距、圆角、阴影、动效

- **间距**：4px 基准网格，只用 4 / 8 / 12 / 16 / 24 / 32 六档。
- **圆角**：控件 6px；卡片/面板 8px；徽标 pill（全圆角）。
- **阴影**：卡片**不用阴影**（用 1px 边框）；阴影仅给浮层（下拉、Dialog、Toast）：`0 4px 16px rgba(0,0,0,.12)`。
- **动效**：150–200ms `ease-out`，仅 hover 过渡、浮层出现、Toast 滑入；日志流滚动无动画。

## 3. 布局

- 内容最大宽 1200px 居中，左右留白 24px；总览表格可占满该宽度。
- 顶栏一行：左侧产品名 `awem`，右侧 daemon/平台连接状态点 + 设置入口。
- 页面骨架统一：**标题行（页面标题 + 主操作按钮）→ 内容区**。不加面包屑（页面仅一层）。
- 不做移动端适配，但宽度 ≤ 768px 时布局不得错乱（允许横向滚动表格）。

## 4. 组件规范

| 组件 | 规范 |
|---|---|
| 按钮 | primary（accent 填充）、secondary（描边）、danger（仅破坏性操作）、ghost（行内图标按钮）。高 32px（紧凑）/ 36px（表单） |
| 状态徽标 | 8px 圆点 + 13px 文字；漂移用 warn 色 pill 徽标（文案"漂移"），挂在执行器名称旁 |
| 表格 | 总览用表格不用卡片列表；行高 44px；表头 12px 次要色；行内操作按钮 hover 显现、焦点显现 |
| 表单 | label 在输入框上方，间距 8px；敏感字段（MCP 令牌、执行器 token）默认掩码 + 眼睛切换 |
| Dialog | 仅用于破坏性确认与编辑；Esc 可关；确认按钮写具体动作（"停止全部执行器"），不写"确定" |
| Toast | 右下角，3s 自动消失；成功用中性色，失败用 danger；失败文案给出下一步 |
| 空状态 | 一句话说明 + 一个主按钮（如"添加第一个执行器"），居中，不堆插画 |
| 加载 | 局部骨架屏或 spinner；禁止整屏白屏等待 |

## 5. 页面级要点（结构以 design.md §9 为准）

- **首次 token 输入**：居中窄卡片（360px），一个输入框 + 一个按钮，无其他元素。
- **总览**：双状态列——"本地进程"与"平台"各自独立列，列头注明来源；行内 start/stop/restart 用 ghost 图标按钮 + tooltip。
- **总览列序**（2026-10-25 起）：名称 | 所属项目 | 所属小队 | 本地进程 | 连接 | 平台 | 模型 | 自启 | 重启 | 操作。
  平台联动启用（任一行有平台数据）才渲染「所属项目」「所属小队」两列，未联动整体隐藏；已联动但
  单条缺数据显示 `—`。名称单元格双行：联动时主行显示平台侧执行器中文名（链接，title 提示所属
  数字工人），副行 12px 等宽显示标识名；未联动时单行等宽标识名。
- **详情**：顶部状态摘要条；**日志查看器无论明暗主题都用暗底**（`#0d1117`）、等宽 13px；渲染 ANSI 颜色；"跟随滚动"开关默认开，用户向上滚动后自动暂停跟随，回到底部恢复；历史日志向上翻页加载。
- **添加/导入**：粘贴区为大号等宽 textarea；解析预览中高亮 `token` / `executor-id` / `model`（accent 底纹）；保存前可逐字段修正。
- **设置**：分组表单（平台联动 / 日志 / 外观），外观组含主题切换（跟随系统 / 浅色 / 深色）。

## 6. 文案与可访问性

- v1 全中文，文案走语言包（design.md D5）；按钮以动词开头（"添加执行器"）。
- 错误文案 = 发生了什么 + 怎么办（例："daemon 未运行且自动拉起失败：…请执行 `awem service install`"）。
- 对比度满足 WCAG AA（正文 ≥ 4.5:1）；所有功能可键盘到达；焦点环为 2px accent outline，不得 `outline: none`。

## 7. 实现约定

1. 主题：默认跟随系统，设置页可手动覆盖，选择存 localStorage；切换不刷新页面。
2. 不强制组件库；若引入，必须可 tree-shake 且样式可覆盖到本规范。图标统一用线性图标集（如 lucide）。
3. **新增状态语义、新组件、新令牌时，先更新本规范，再写代码**（与仓库"先改文档"约定一致）。
