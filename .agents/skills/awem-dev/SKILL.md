# awem 开发任务执行

仓库：`awem`（Go 单二进制 + React SPA；2026-10-25 由 `autowonder-executor-manager` 改名，
GitHub 旧名自动重定向）。开发任务计划与全部状态落在
`docs/task-awem-dev/`（1 个索引 + 11 个子任务 + 1 个共享规范）。本技能的职责：**按计划推进开发，并让任务状态文档始终反映真实进度**。

## 固定流程（每次触发都从第 1 步开始，不凭记忆）

1. **读索引**：`docs/task-awem-dev/index.md` → 总状态、子任务表、推荐顺序。
2. **读规范**：`docs/task-awem-dev/conventions.md`（所有子任务必守）+ `AGENTS.md`；涉 Web UI 再读 `docs/design/ui-guidelines.md`。
3. **定位用户意图**：
   - 指定了编号（"执行 T04"“检查 T02”）→ 该子任务；
   - "继续/下一个"→ 推荐顺序中第一个非 ✅ 的子任务；
   - "进度/还剩什么"→ 汇报 index.md 状态表（读各子任务文档顶部状态即可），结束。
4. **开工前**：通读目标子任务文档全文（功能点、验收要点、规范速查）及其"设计依据"指向的
   design.md 章节；把子任务状态 ⬜→🔄，同步 index.md，双方变更记录各加一行（日期 + 动作 + 一句话）。
5. **开发**：逐功能点实现——先读该功能点的"开发描述"与"验收要点"再动手；**完成一个功能点就立即**
   把它的开发状态改 🟠 并同步 index.md 进度列（`已检查数/总数`），不要攒到最后批量改。
6. **收尾**：全部功能点 🟠 且 `go build ./...`、`go vet ./...`、`go test ./...` 三绿 → 子任务状态 🟠
   （待检查），汇报完成情况。**不自行把子任务标成 ✅ 已检查**——检查是独立环节。
7. **检查模式**（用户说"检查 T0X"或开发完成后要求自查时）：逐功能点实际执行"验收要点"里写的
   验证手段（跑测试、跑命令、读代码对照设计），**不许凭印象打勾**。通过 → 功能点检查状态 ✅、
   "检查记录"表加行；不通过 → 该功能点开发状态打回 🔄、检查状态 ❌、登记问题，子任务状态回 🔄。
   全部功能点 ✅ → 子任务状态 ✅、index.md 同步；最后一个子任务 ✅ 后把 index.md 总任务状态改 ✅。
8. **暂停**：用户要求停下或会话必须中断时：子任务状态 ⏸️，变更记录写明"已完成到哪、暂停原因、恢复前提"。

## 硬性规则（违反任何一条即停下向用户报告）

- **文档优先**：实现与 `docs/design/design.md` 冲突 → 停下，先改设计文档征得用户同意再改代码；
  UI 新增令牌/组件/状态语义 → 先更新 `ui-guidelines.md` 再写代码。（来源：AGENTS.md，最高优先级）
- **红线**：不做任务派发；不做多机聚合；平台只读（MCP 仅 `list_projects`/`list_executors`/
  `get_executor_launch_config` 三工具白名单）；v1 不做内置 MCP server；API 仅绑 127.0.0.1。
- **不跳步**：功能点未完成不许标 🟠；已完成 ≠ 已检查；检查必须逐点跑验收手段。
- **留痕**：状态只增不删，打回/暂停都要在变更记录留原因；两处状态（子任务文档 + index.md）必须同步。
- **工程约定**：注释与文档中文、标识符英文；CLI `--json` schema 稳定、幂等、退出码 0/1/2/3/4/5；
  测试不依赖真实平台与 npx（假长驻子进程）。
- **实现细节选型**（库、状态枚举、默认值等设计未定项）自行决定，但必须记入该子任务文档"变更记录"。

## 状态字典

子任务状态 / 功能点开发状态：⬜ 未开始 · 🔄 进行中 · ⏸️ 已暂停 · 🟠 已完成（待检查） · ✅ 已检查。
功能点检查状态：⬜ 未检查 · ✅ 通过 · ❌ 不通过（打回 🔄）。
完整状态机与更新规则见 `docs/task-awem-dev/conventions.md` §6–8。

## Git 提交节奏（用户要求"边做边提交"或夜间长任务时执行）

- **一个功能点一次提交**：功能点开发完成且自检（实际执行验收要点）通过 → 把相关代码与状态文档（子任务文档 + index.md）放进**同一个提交**，提交信息格式 `T0X(FY): 一句话中文说明`（如 `T03(F2): 结构化字段解析与校验`）。
- **一个子任务一次推送**：子任务全部功能点 ✅ 且 index.md 同步后 → `git push`。
- 提交前必须三绿（`go build/vet/test`）；⏸️ 暂停记录也提交（`T0X: ⏸️ 原因`），保证仓库状态即真实进度。
- 未初始化 git 或无远端时跳过本节，照常只更新状态文档。

## 恢复中断的工作

继续任何 ⏸️/🔄 子任务前：读该子任务文档的变更记录与检查记录，从未完成的功能点接着做，不重做已完成项。
